# Suggestion entry format

One file per suggestion in `.hivemind/suggestions/`, named
`YYYY-MM-DD-<pp|po>-<slug>.md` (your role's initials):

```
**Date:** YYYY-MM-DD
**Project:** [repo name]
**Role:** <role name> — any role when the keeper asks
**Scope:** repo | harness (harness = a bee skill/template/rule)
**What happened:** one or two sentences, concrete
**Suggestion:** the change someone could make (skill edit, template fix,
rule change, tooling request)
```

Act-on-able only. "Improve X" is not a suggestion; "add Y to template Z
because W" is.

A problem with no proposed solution is a legitimate suggestion file —
state the problem concretely; graduation treats it as a design input.
