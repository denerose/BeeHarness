# Suggestion — hindsight: route findings by control axis, not by owner

**Date:** 2026-11-07
**Project:** BeeHarness
**Role:** power-planner (keeper direction, hindsight #2 follow-up)
**Scope:** harness (bee-hindsight skill — joins item 6's P8 pass)

## What happened

Hindsight #2 declared "no suggestion files — behavioral lessons go
to the memory store." The keeper challenged it: half the point of
a harness is controlling behavior. The error: findings were routed
by WHOSE failure they were (a role's habit → that role's memory)
instead of by WHAT SHOULD CONTROL THE BEHAVIOR going forward
(graduation into law, role files, standards, skill text = binding
on every role and future context).

## Suggestion

A routing rule in bee-hindsight's "What to produce" section:

> Route each finding by its control axis, not its owner. The
> memory store seeds the correction (wake-time checklines for the
> role that failed); a suggestion file opens the graduation path
> whenever the behavior should bind beyond one role — which is
> almost always. A finding skips the suggestion file only if
> controlling no one but the filing role is genuinely correct.

Reference: the plain-relations / binary-rulings / artifact-first
trio (all mis-routed to memory-only, all corrected into
suggestions on keeper challenge, 2026-11-07).
