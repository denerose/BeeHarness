# Suggestion — class rulings are binary per class

**Date:** 2026-11-07
**Project:** BeeHarness
**Role:** power-planner (hindsight #2, keeper-challenged routing)
**Scope:** repo (GLOSSARY escalate entry or the ask-hygiene law — cross-role)

## What happened

The commit-record ruling: my first recommendation offered a
middle-ground cadence (squash some classes at some times); the
keeper rejected it flat — "a: yes it belongs in git or b: no it
does not. No middle ground fluff." WHEN-to-commit rules are
rule-overhead; binary per class is the shape the keeper wants for
class rulings.

## Suggestion

Add to the ask-hygiene law (GLOSSARY escalate entry):

> A ruling over a class of things is framed binary per class — in
> or out, yes or no. Middle-ground cadences are rule-overhead. A
> genuine hybrid may exist only as its own named option, never as
> a hedge between the real ones.

Seed: ME-PP-002. Applies to every role that puts a ruling to the
keeper.
